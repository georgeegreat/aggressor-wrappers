fix(export): declare PATH, and let a gap be a gap

Two failures on one export, both of them this package telling amyloscope
something that stopped being true.

AMYLOSCOPE_TOOL_NAMES still mapped path to None, with a comment explaining that
amyloscope has no adapter and no mechanism family for it. It has both now. The
consequence was the worst-shaped one available: export_protein wrote PATH's
seven tracks to disk, build_amyloscope_config left the tool out of the config
that declares them, and the warning said the tracks "remain on disk under
tracks/" -- so the data was present, visible, and not in the panel. A fractional
consensus counts what it loads.

The mapping is a hand-written mirror of amyloscope's adapter registry and will
drift again; what it now has is a test pinning path, and a companion test that
pins the skip mechanism against a deliberately unmapped predictor rather than
against whichever one happens to be unsupported today. Nothing maps to None any
more, and the old test asserted exactly that it did.

The second failure outlived the first. The config carries ONE tools list and one
path template, so a tool is declared for every protein; a tool with no data for
one of them therefore declared a track that was never written, and verify_export
refused the entire export. One unreadable raw file in a seven-protein panel made
the other six unusable -- the same shape as the scheduler's parse loop and the
merge step, in a third place.

A gap is now written down rather than fatal: a placeholder track of NaN scores
for that protein. NaN says this tool predicted NOTHING about this protein, which
is what happened; zeros would say it looked and found nothing, which it did not.
It is the same marker a truncated submission already uses for the residues it
did not cover, so amyloscope needed no change to read it -- the tool contributes
no calls, and the coverage is reported per protein. The export warns, naming
every (protein, predictor) pair it had to fill.

verify_export's advice was wrong for this case and only for this case. It
offered stale tracks from an earlier export as "the usual cause" under every
failure, including "declared in the config but absent", which is that cause's
exact opposite: a reader following it cleans the directory, re-exports, and gets
the same error. The hint is now offered only where it could apply.

Checked against the panel this came from, unchanged: twelve predictors declared
including PATH, RPS12's missing WALTZ track written as not-predicted, the export
loadable, and amyloscope running it through to a report that states RPS12 as
foldamyloid 120/132 and waltz 0/132. Six tests. 564 pass, 7 skip.

Still commented out in config.cfg, deliberately, since it is a claim about what
was submitted rather than a default: [predictors.waltz] offsets = RPS12:9.
Uncommenting it gives RPS12 a real WALTZ track in place of the placeholder.
